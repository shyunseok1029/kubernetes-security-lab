# Helm 배포 수명주기 개인 실습

## 목적과 개념

개인 Kubernetes 환경에서 Helm Chart를 이용한 배포와 Release의 변경·복원 흐름을 살펴봤습니다. Chart는 Kubernetes 리소스의 배포 구성을 묶는 형식이고, Release는 Chart를 설치해 관리하는 배포 단위입니다. Revision은 Release 변경 이력을 구분합니다.

## 수행 내용과 확인 결과

개인 실습 PDF와 터미널 캡처를 요약한 기존 조사 기록에 다음 흐름이 남아 있습니다.

1. Chart를 설치하고 Release를 확인했습니다.
2. replica 설정을 변경해 Upgrade했습니다.
3. History에서 Revision 이력을 확인했습니다.
4. 이전 Revision으로 Rollback하고 복원 상태를 확인했습니다.

이 과정은 배포 설정의 변경과 이전 상태로의 복원을 이해하는 데 초점을 맞췄습니다. Chart를 직접 제작했는지, 운영 환경에 적용했는지 또는 별도의 안정성 성과가 있었는지는 확인된 범위에 포함하지 않습니다.

## 근거와 한계

기존 조사에는 개인 PDF와 터미널 캡처가 근거로 기록되어 있지만, 해당 실습은 개인 Git 커밋으로 보존되지 않은 상태였습니다. 원본 캡처의 출처·권리와 민감정보를 확인하기 전에는 이미지를 게시하지 않습니다. 이번 문서 작성에서 설치·업그레이드·롤백을 다시 실행하지 않았습니다.
